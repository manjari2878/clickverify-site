# ClickVerify Privacy Policy

**Last updated: October 5, 2026**

This policy describes the ClickVerify local beta. It is not a statement that the extension is approved or listed in the Chrome Web Store.

## What runs, and when

ClickVerify processes visible text in the main document, and labels of visible selected checkboxes, only after the person clicks **Check this page**.

The scan looks for a small set of phrases and for those checkbox labels. It can show a short nearby-text excerpt, the page hostname, and the time of that scan inside the popup.

## What the extension does not do

ClickVerify does not intentionally collect, transmit, sell, retain, or share:

- page content
- form input values
- payment details
- passwords
- account credentials
- browsing history
- scan results

It does not use analytics, ads, remote code, or a backend.

It does not keep a scan history. Closing the popup discards the result. The extension has no account and no server.

## Limits of the scan

The scan does not inspect cross-origin frames. Dynamic content can be missed.

The extension reads visible text that is already on the page. It does not read form field values. If payment details, a password, or other sensitive text is already visible as page text, a nearby excerpt can include it on screen. That text is not transmitted or saved.

The tab address is checked only to skip pages that are not regular `http` or `https` pages. The query string and fragment are not put in the report.

## What a result means

ClickVerify does not certify safety, verify merchants, or determine whether a page is fraudulent or a scam.

It is a local beta. Its supported signals are limited to urgency wording, recurring-payment wording, a few explicit local renewal denials, and visible selected checkboxes.

No supported signals is not a reason to treat a page as acceptable. An error means the page was not scanned.
